# Product Direction

- LifeWise is a consumer AI life decision and execution assistant for people with limited independent-living experience, not a general Agent platform.
- Product outcome: help a user complete a real-world task through guided diagnosis, actionable steps, safety boundaries, and outcome confirmation.
- All ten scene entries now use task-appropriate guided workflows: repair troubleshooting; cooking and housework execution; health and pet safety triage; shopping, fashion, and meal-plan decisions; etiquette rehearsal; and writing draft iteration.
- Guided choices fill the composer instead of immediately sending, so users can add context; submitting locks that card's choices and outcome actions to prevent duplicate requests.
- `npm run test:ai` performs live acceptance for all ten scenes using process-only `AI_API_KEY`; the response cap matches application requests at 4096 tokens.
- User questions are persisted before the AI request so browser/WebView recreation never opens an empty conversation; the just-persisted question is excluded from that request's context, and retries reuse it without duplication. Guided-scene JSON parse failures retain readable body text and offer card regeneration instead of exposing raw model payload.
- Failed chat cards retain a retry payload (message, scene, follow-up mode, and image URL) and reuse the same card. Scene-image polling stops after three minutes, cleans up on unmount, and exposes retry after failure or timeout.
- Live AI acceptance retries transient 429, 5xx, and network failures up to three attempts with exponential backoff. Export, writing-mode, and image quick actions are native keyboard-reachable buttons.
- Browser and Android both stream responses. Android resolves the native completion event before asynchronously removing listeners; non-streaming JSON remains only as a fallback.
- Chat accepts one request at a time and always clears loading/current-typing state plus stale typing cards in `finally`.
- Chat recovery: remember the active conversation for two minutes per scene; persist a completed conversation URL only after its messages are saved. The active request ignores its own persistence event to avoid a competing reload.
- Browser click and Enter sends call `send()` without passing DOM events as retry payloads. User bubbles render Markdown only; assistant cards alone use structured rendering. Stream UI batches content updates at 100ms and scrolls once per animation frame.
- Backend and local AI paths share the ten-scene guided-workflow contract. Follow-ups in cooking, shopping, repair, housework, health, fashion, etiquette, pet, and mealplan retain structured task state; only writing and general queries use natural-language follow-ups. Frontend tests guard this contract and mount `Chat.vue` for send, retry, structured-card, and guided-choice-locking behavior.
- Repair, health, and pet have deterministic safety gates before knowledge-base lookup and AI calls. Repair detects gas, electrical/fire, and major leak risk; health detects emergency cardiopulmonary, consciousness, severe allergy, bleeding, and persistent-high-fever signals; pet detects respiratory, seizure, poisoning/foreign-body, and severe-injury signals. Each returns a scene-compatible structured escalation card.
- Health and pet server-side prompt schemas now match the local guided contract: risk stage/status, a single next action, observable records, checklist, mutually exclusive choices, escalation conditions, and follow-up actions.
- The browser defaults to `src/local/aiClient.js`, so it runs the same repair/health/pet safety triage before checking AI configuration or creating a network request. `safetyTriage.test.js` covers its emergency and ordinary paths.
- Live acceptance against the configured OpenAI-compatible endpoint passed all ten scenes with `gpt-5.6-terra`; the synchronized Android Debug APK also compiled successfully.
- The Vite development proxy target must match the browser-configured AI endpoint origin. It currently targets `https://api.caijiyun.top`, preventing direct-browser CORS failures during local AI connection tests.
- The chat title is editable for persisted conversations. Key icon-only controls expose accessible names and a visible keyboard focus indicator.
- Reuse the existing chat history and structured scene cards for the first version. Do not add a general workflow engine or persistent agent-state table yet.
- Relevant references: Rasa for slot filling and clarification; Dify for workflow/evaluation; Open WebUI for local model, memory, and chat interactions; Coze Studio for future agent orchestration; Home Assistant for device-state modeling.
